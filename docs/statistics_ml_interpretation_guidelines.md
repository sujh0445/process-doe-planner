# Statistics and ML Interpretation Guidelines

목적: 통계/ML 자료를 프로젝트에 적용할 때 공통으로 지킬 해석 기준을 정리한다. 이 문서는 특정 모델 성능을 주장하기 위한 문서가 아니라, 데이터 분석 결과를 과장하지 않고 재현 가능하게 설명하기 위한 기준이다.

## 1. 데이터 이해 원칙

- 한 행(row)이 무엇을 의미하는지 먼저 정의한다.
- 한 열(column)이 어떤 변수인지 확인한다.
- 변수는 수치형, 범주형, 시간형, 식별자형으로 구분한다.
- 모델링에서는 입력 변수를 `feature`, 예측하려는 값을 `target` 또는 `label`로 부른다.
- 실험계획에서는 조작하는 변수를 `factor`, 측정하는 결과를 `response`로 부른다.
- ID, timestamp, 사후 검사 결과처럼 결론을 암시하는 컬럼은 분석 변수로 쓰기 전에 누수 가능성을 점검한다.

## 2. 기술통계 원칙

- 평균만 보지 않는다.
- 평균, 표준편차, 중앙값, IQR, min/max, 이상치 후보를 함께 확인한다.
- 히스토그램과 박스플롯으로 분포 모양을 본다.
- 치우친 분포에서는 평균보다 중앙값/IQR이 더 안정적인 요약일 수 있다.
- 이상치는 제거 대상이 아니라 먼저 원인을 확인해야 하는 관측값이다.

## 3. 확률과 분포 해석 원칙

- 확률은 불확실성을 숫자로 표현한 값이다.
- 조건부확률 `P(A | B)`와 `P(B | A)`를 혼동하지 않는다.
- 정규분포는 중요하지만 모든 데이터가 정규분포를 따른다고 가정하지 않는다.
- z-score는 값이 평균에서 몇 표준편차 떨어졌는지 보는 표준화 지표다.
- t-분포, 카이제곱분포, F-분포는 평균/분산/그룹 차이 검정의 이론적 기반으로 사용한다.

## 4. 표본과 추론 원칙

- 표본은 모집단의 일부이며, 표본 통계량은 표본 선택에 따라 흔들린다.
- 표준편차는 개별 데이터의 퍼짐이고, 표준오차는 추정값의 불확실성이다.
- 신뢰구간은 추정값의 불확실성을 범위로 표현한다.
- 95% 신뢰구간은 "이 구간에 모수가 있을 확률이 95%"라는 단정이 아니라, 같은 절차를 반복하면 약 95%의 구간이 진짜 모수를 포함한다는 뜻이다.

## 5. 가설검정 원칙

- 가설검정은 "차이가 없어도 이런 데이터가 나올 수 있는가"를 보는 절차다.
- p-value는 내 가설이 맞을 확률이 아니다.
- p-value는 귀무가설이 맞다고 가정했을 때 현재 관측값만큼 또는 더 극단적인 결과가 나올 확률이다.
- `p < alpha`이면 귀무가설을 기각하지만, 이는 인과를 증명하지 않는다.
- `p >= alpha`는 차이가 없다는 증명이 아니라, 현재 데이터로 차이를 말할 근거가 부족하다는 뜻이다.
- 1종 오류는 실제 차이가 없는데 차이가 있다고 판단하는 오류다.
- 2종 오류는 실제 차이가 있는데 잡지 못하는 오류다.
- 검정력은 실제 차이가 있을 때 이를 잡아낼 확률이다.

## 6. 실험과 모델링 원칙

- 실험 목적을 먼저 정의하고, 그 목적에 맞게 factor와 response를 정한다.
- 회귀는 연속형 response를 설명하거나 예측한다.
- 분류는 class 또는 label을 예측한다.
- 같은 데이터라도 target/response 정의에 따라 문제 유형이 달라진다.
- tree/ensemble 모델은 비선형 관계와 interaction을 잡는 데 유리하지만, DOE 해석에서는 factor effect와 trade-off를 별도로 정리해야 한다.

## 7. 모델 평가 원칙

- accuracy만으로 모델을 평가하지 않는다.
- Positive class가 드문 문제에서는 confusion matrix, recall, precision, F1, PR-AUC, FN/FP count를 함께 본다.
- threshold는 모델 자체가 아니라 score를 decision으로 바꾸는 운영 기준이다.
- ROC-AUC는 전반적인 구분 능력을 보지만, 불균형 데이터에서는 PR curve도 함께 확인한다.

## 8. 실험 분리와 누수 방지 원칙

- train은 모델 학습용이다.
- validation은 모델, feature, threshold, hyperparameter 선택용이다.
- test는 최종 평가용이며 마지막에 한 번만 사용한다.
- test 결과를 보고 모델이나 threshold를 바꾸면 test leakage다.
- scaling, imputation, encoding 등 전처리 기준은 train에서 fit하고 validation/test에는 transform만 적용한다.
- DOE 실험에서는 확인 실험(confirmatory run)을 탐색 실험(screening run)과 구분한다.

## 9. Feature와 Factor 해석 원칙

- feature importance는 예측 기여도이지 인과 증거가 아니다.
- DOE의 factor effect도 실험 범위와 response 정의 안에서 해석해야 한다.
- 상관 높은 factor/feature가 많으면 개별 효과 해석이 불안정할 수 있다.
- 개별 변수보다 factor group 또는 process mechanism 단위 해석이 더 안전할 수 있다.

## 10. Calibration과 Score 원칙

- 모델 score가 0.8이라고 해서 자동으로 실제 확률 80%라는 뜻은 아니다.
- 확률처럼 말하려면 calibration curve, Brier score 등으로 확인해야 한다.
- calibration을 하지 않았다면 score는 상대적 위험 또는 추천 점수로 표현한다.

## 11. 보고서 표현 원칙

- 결과와 해석을 구분한다.
- 성능 숫자 또는 실험 score는 선택 기준과 함께 제시한다.
- feature importance나 factor effect를 인과처럼 과장하지 않는다.
- 한계를 숨기지 않는다.
- "완벽히 예측했다", "원인을 규명했다" 같은 과장 표현을 피한다.

## 12. 안전한 표현 예시

위험한 표현:

```text
이 factor가 불량 원인이다.
```

권장 표현:

```text
해당 factor는 본 실험 범위에서 response 변화와 일관된 관련성을 보였으며, 원인성 확정을 위해서는 추가 확인 실험이 필요하다.
```

위험한 표현:

```text
추천 조건이 최적 조건이다.
```

권장 표현:

```text
추천 조건은 현재 objective와 guardrail 기준에서 가장 유리한 후보 조건이며, confirmatory run으로 재검증해야 한다.
```
